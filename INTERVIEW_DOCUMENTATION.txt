Problem Statement:
Deaf and hard-of-hearing individuals face communication barriers in daily life. Existing sign language learning tools often lack personalized feedback and real-time recognition. Gesture-Ease aims to provide an accessible, interactive platform for independent practice using computer vision and deep learning.

Solution:
Gesture-Ease is a full-stack gesture recognition platform that uses MediaPipe hand landmarks and a BiLSTM-based neural network to interpret sign language gestures. The system provides instant verification, feedback, progress tracking, and a community-style leaderboard.

================================================================================
MACHINE LEARNING COMPONENT
================================================================================

1. DATA COLLECTION & PREPROCESSING

Dataset and Features:
- Uses hand landmark sequences extracted with MediaPipe Hands
- Each frame produces up to 2 hands × 21 landmarks × 3 coordinates = 126 features
- The backend can process frame data from a live camera or precomputed landmark vectors

Data Processing Pipeline:
a) Frame Processing
   - Decode base64 image frames from the frontend
   - Resize frames to 640×480 for stable MediaPipe input
   - Convert BGR to RGB before MediaPipe processing

b) Hand Landmark Extraction
   - Extract up to 2 hands per frame
   - Zero-pad missing hand landmarks when only one hand is visible
   - Output a 126-dimensional feature vector per frame

c) Sequence Normalization
   - Standardize gesture input to 30 frames
   - If more than 30 frames are provided: sample uniformly to 30 frames
   - If fewer than 30 frames are provided: pad with the last available frame
   - Final input shape: (30, 126)

d) Feature Normalization
   - Load a saved StandardScaler artifact from `artifacts/scaler.pkl`
   - Normalize the flattened sequence before model inference

2. MODEL ARCHITECTURE

BiLSTM Neural Network (from training implementation):

Input Layer:
- Shape: (30, 126)

Recurrent Layers:
- Bidirectional LSTM layer with 128 units, return_sequences=True
- Batch normalization
- Bidirectional LSTM layer with 64 units, return_sequences=False
- Batch normalization

Attention and Dense Layers:
- Attention-like weighting over time steps for sequence focus
- Dense layers with 256, 128, and 64 units
- Dropout and batch normalization used for regularization

Output Layer:
- Softmax over gesture classes
- The backend loads model artifacts from `models/best_model.h5`, `models/model.h5`, or `models/model.keras`

Why BiLSTM?
- Captures temporal patterns in gesture sequences
- Bidirectional processing improves context understanding
- Suitable for landmark sequences with time dependencies

3. MODEL TRAINING

Training Configuration:
- Optimizer: Adam
- Loss Function: Categorical cross-entropy
- Batch Size: 32
- Epochs: up to 150 with early stopping
- Validation Split / validation dataset used during training

Model Artifacts:
- Trained model saved in `models/`
- Label map loaded from `artifacts/word_mappings.json` or `labels.json`
- Scaler saved in `artifacts/scaler.pkl`

4. INFERENCE & PREDICTION

Real-Time Prediction Pipeline:

Step 1: Receive input
- Frontend sends either raw frame base64 data or landmark sequence payload
- Backend accepts `/api/predict/sign` for raw frames and `/api/predict_landmarks` for precomputed landmarks

Step 2: Landmark Extraction
- MediaPipe Hands detects landmarks on each frame
- The system produces a fixed-length sequence of 126-d vectors

Step 3: Preprocess
- Normalize with the saved scaler
- Reshape to `(1, 30, 126)`

Step 4: Model inference
- Run the BiLSTM model to get softmax probabilities over classes

Step 5: Post-processing
- Apply confidence thresholds for valid predictions
- Provide top-k predictions with probabilities
- Generate user feedback messages

Step 6: Result
- Return prediction results with confidence, feedback, and leaderboard/attempt tracking metadata

5. CONFIDENCE SCORING & FEEDBACK

Confidence Thresholds:
- Minimum confidence for verification: 25%
- Higher confidence yields more positive feedback and higher points

Point System:
- Confidence >= 60%: 15 points
- Confidence 40-60%: 10 points
- Confidence 25-40%: 5 points
- Confidence < 25%: 0 points

Feedback Messages:
- High confidence + correct: “Excellent! Perfect execution!”
- Medium confidence + correct: “Good job! Keep practicing!”
- Low confidence + correct: “Correct but try to be clearer!”
- Incorrect: “Try again. Gesture not clear enough.”

BACKEND DEVELOPMENT
================================================================================

1. TECHNOLOGY STACK

Framework: Flask
Database: MySQL with SQLAlchemy ORM
Authentication: JWT (JSON Web Tokens)
API Style: RESTful
Server: Gunicorn recommended for production

2. API ENDPOINTS

Authentication Endpoints:
POST /api/auth/register
- Register new user
- Request: { email, username, password }
- Response: { success, token, user }

POST /api/auth/login
- Login existing user
- Request: { email, password }
- Response: { success, token, user }

GET /api/auth/me
- Get current user profile
- Headers: Authorization: Bearer {token}
- Response: { success, user }

Gesture Recognition Endpoints:
POST /api/predict_landmarks
- Predict gesture from landmark sequence
- Request: { target_word, landmarks }
- Response: { is_correct, target_word, target_confidence, points, message, top_predictions }

POST /api/predict/sign
- Predict gesture from a raw frame
- Request: { frame_base64 }
- Response: { predictions, buffer_status, frame_with_overlay_base64 }

POST /api/predict
- Compatibility endpoint that redirects to `/api/predict_landmarks`

User Management Endpoints:
POST /api/attempt
- Save gesture attempt to the database
- Request: { user_id, target_word, is_correct, points, message, top_predictions }
- Response: { success, attempt_id, user_stats }

GET /api/user/<user_id>/progress
- Retrieve word progress for the user
- Response: { success, username, progress }

GET /api/user/<user_id>/attempts
- Retrieve recent gesture attempts
- Response: { success, username, attempts }

Search & Discovery Endpoints:
GET or POST /api/search
- Search available gesture words by query
- Response: { success, words, total_found, total_classes }

GET /api/words
- Retrieve all available gesture words
- Response: { success, words, total_classes }

System Endpoints:
GET /api/status
- Check backend health and model load status
- Response: { success, status, model_loaded, total_classes, ready_for_predictions }

GET /api/model_info
- Retrieve model metadata and class count
- Response: { success, num_classes, sequence_length, feature_dim }

POST /api/session/start
- Reset prediction buffer for a new gesture session

POST /api/reset_buffer
- Clear the backend frame and prediction buffers

POST /api/debug_landmarks
- Debug landmark extraction quality for a small set of frames

GET /videos/<filename>
- Serve video assets from available local directories

3. JWT AUTHENTICATION

Token Generation:
- Payload includes user_id, username, issued-at, and expiration
- Signed with HS256
- Expiry controlled by `JWT_EXPIRATION_HOURS`

Token Verification:
- Validate token on protected endpoints
- Reject expired or invalid tokens

Token Usage:
- Stored in frontend local storage
- Sent with Authorization header: Bearer {token}

4. ERROR HANDLING

Error Response Format:
{
    "success": false,
    "error": "Error message"
}

Common Errors:
- 400: Bad Request
- 401: Unauthorized
- 404: Not Found
- 500: Internal Server Error

Logging:
- Flask logs requests and prediction flow
- Detailed tracebacks are logged on server errors

CHALLENGES & SOLUTIONS
================================================================================

Challenge 1: Real-Time Performance
Problem: Model inference must remain fast for live feedback
Solution:
- Optimized model architecture with BiLSTM
- Buffered frames and incremental prediction
- Cached model loaded at startup

Challenge 2: Gesture Variability
Problem: Same sign looks different across users
Solution:
- Landmark-based input reduces raw visual variation
- Temporal sequence normalization
- Confidence thresholds and smoothing

Challenge 3: Hand Detection Failures
Problem: Hands not detected in some frames
Solution:
- Use MediaPipe with minimum detection confidence
- Zero-pad missing hands and continue processing
- Provide feedback when input is incomplete

Challenge 4: Database Tracking
Problem: Need to store progress and leaderboard data reliably
Solution:
- SQLAlchemy models for users, attempts, and progress
- Aggregate leaderboard from gesture attempts
- Use indexed fields for performance

Challenge 5: Model Accuracy
Problem: Initial predictions were unstable
Solution:
- Improved preprocessing and frame normalization
- Used model regularization, batch normalization, and dropout
- Designed scoring and feedback around confidence bands
